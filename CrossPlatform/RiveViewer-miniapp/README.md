# RiveViewer Miniapp

一款在微信小程序和独立 H5 中预览、检查和交互调试动效文件的工具。微信小程序与 H5 本地版只在当前设备保存；JOJO 托管版会把用户主动选择或拖入的文件上传到云端并生成公开链接。

 
JOJO 前端已于 2026-09-11 发布提交 `3c0233e`（发布版本 `20260911-172135`），包含顶层按钮气泡、单按 L 复制链接、详情快捷键、归档入口与文件右键菜单。

## 详情页快捷键

预览详情右上角保留键盘帮助入口；按钮悬停显示操作与快捷键。Mac 使用 Command U 上传新版本、单按 L 复制链接、Command E 下载；Windows / Linux 的上传与下载对应 Ctrl，复制同样单按 L。上传与复制仅适用于云端文件，编辑输入、弹窗与菜单期间不触发文件操作。

复制链接使用 L，不再尝试覆盖浏览器的 Command / Ctrl L。操作提示气泡通过 Portal 与浏览器顶层显示，避免被预览区域遮挡。

### 微信小程序码

 
 
本版统一小程序/H5 的画布手柄、缩放快捷项和 Gentle 弹簧反馈；复杂文件继续自动限制 DPR 与帧率，实时 FPS 仅显示在播放时间右侧。

 
 
 
## 核心功能

- 从微信聊天文件批量导入，最多一次选择 100 个 `.riv` 文件。
- 支持可用环境中的系统文件多选；不支持时自动只展示聊天文件入口。
- 微信小程序内置两份示例文件，示例和已导入文件都可从本地列表删除；示例删除后以本地隐藏记录保持不再出现，清除小程序数据可恢复。
- 微信小程序首页的导入框、文件行、操作箭头、文件菜单、复制按钮和反馈入口都有即时放大回弹；小型按钮按下放大到 `1.25×`，大面积导入框与文件行使用 `1.025×` 避免遮挡。小程序文件操作菜单只保留“发送文件、删除文件”；H5 不提供不可恢复删除。
- 首页底部单行展示“复杂文件用网页版更流畅：”、`mikeywa.site/rive-viewer/` 和复制图标，整行左右各有 `20px` 内边距；空间不足时网址末端以黑色渐隐遮罩表示截断，遮罩与复制按钮无缝衔接。复制内容仍为完整的 `https://mikeywa.site/rive-viewer/`，成功后提示“已复制网址”。
- 底部“联系作者反馈意见”与网页版提示统一使用 `24rpx` 字号。
- 读取画板、状态机、时间轴和状态机输入；支持 Trigger、Boolean、Number 等交互。
- 支持完整/铺满、五种画布背景、播放暂停、重置、`0.5x / 1x / 1.5x / 2x / 8x` 倍速；单击画布手柄会在原位展开“完整 / 铺满”并在 `3s` 后自动收起，按住或拖动时手柄高亮并继续支持上下调高、横向滑选，`500ms` 内双击直接在完整与铺满之间切换。手柄默认较粗、展开后变细，左右项以淡黄色背景和同步变黄的 Phosphor Bold 图标/文字反馈，并使用约 `420ms` 的 Gentle 弹簧展开与反向收起。小程序在 `touchend` 内完成单/双击判定，不依赖可能因布局更新而丢失的后续合成 `tap`；手指轻微抖动的容差为 `16rpx`。
- 预览菜单所有可操作按钮按下即从中心放大到 `1.25×`，松开以弹簧曲线复位；播放速度和文件切换按住 `150ms` 即展开菜单，点菜单外空白区域可取消并收起。文件菜单支持不松手滑到任意文件，目标行即时高亮，松手直接打开。
- 画布下方的重播、播放/暂停、播放速度、上一个、下一个共五个按钮按五等分平等撑满整行，小程序独立详情、Mac 同页预览和 H5 保持一致。
- 小程序与 H5 的功能图标统一使用 Phosphor Icons `Bold`，由同一脚本固化成本地 SVG；H5 通过 CSS Mask 按需请求当前页面使用的图标，不再打包整套 React 图标库。
- 小程序五格工具栏把重播、播放/暂停、倍速、上一个、下一个改为五个非原生 `view role="button"` 一级项；使用 `width: 0; flex: 1 1 0` 严格等分，规避微信端原生 `button` 将百分比宽度按整行计算并覆盖翻页按钮。
- H5 时间轴标签在通用标签基础上左右各增加 `14px` 内边距；当前时间轴使用独立黄色半透明填充层显示实时播放进度，标签文字始终保持白色。播放时长优先从动画定义的工作区帧数与 FPS 计算，兼容运行时实例不暴露 duration 的文件；OneShot 结束强制填满，Loop 与 PingPong 分别回绕和往返。
- H5 控制区第一栏为事件控制台：折叠时显示当前文件最新事件，展开后显示本次打开期间最近 `200` 条绑定、播放、状态切换和 Rive Event；OpenUrl 只记录，不自动跳转。
- 参数顺序为状态机输入后紧接预览背景；H5 在缩放方式后以“渲染引擎”收尾，小程序仍以缩放方式收尾。背景色块使用 `60rpx × 40rpx` 易点按短胶囊，Loading 进度环保持正圆。
- 默认按 `in → idle → out` 组织常见时间轴；带 Listener 的状态机优先接管用户点击。
- 画布触摸事件直达 Rive 状态机；Piano Game 一类嵌套 Listener 与 View Model 文件可交互。
- 首页首屏稳定后预热 Rive WASM，点击文件时也会立即启动；不在首页预解析 `.riv`，避免大文件常驻内存。
- 大文件分块读取、分阶段 Loading、初始化前先刷新加载界面、按文件大小限制像素比、复杂文件约 30fps 渲染、加载超时重试和离页资源释放。
- Piano、Animojis 等嵌入资源较多的文件支持图片格式识别、图片失败回退、兼容版 WASM 和 DOMMatrix 适配。
- 含音频的 Rive 文件默认开启声音；参数区提供“开启 / 静音”开关并记住用户选择。
- iPhone 上的 Piano 会拦截全部内嵌音频，12 个琴键音使用 `WebAudio BufferSource` 直接播放，不再启动 Rive `ScriptProcessor/miniaudio`；恢复期连点只保留最新音符，最多同时保留 16 个音源。
- iOS 含音频文件使用约 30fps、像素比上限 `1.5`和状态反馈节流，减少动画、音频和视图更新争抢主线程。
- 超过 8 MB 的文件自动跳过音频解码并显示“性能保护”，避免声音资源使大文件加载和返回再次卡住。
- 上一个/下一个文件快速切换；长按可打开完整文件列表。
- Mac/Windows 与开发者工具在窗口宽度达到 `960px` 时，文件列表和 Rive 预览在同一个小程序页面内左右并排，不再触发微信 Mac 原生双 WebView 白色分隔线。
- `h5/` 提供独立浏览器版：预览详情不分 Tab，画板、状态机、时间轴、输入、声音、缩放、背景和渲染质量在同一页；入口固定为 `/rive-viewer`。

### 2026-08-17 整体重构结果

- H5 播放指标改为局部订阅，根组件不再承接时间轴/FPS 高频状态；元数据计算按 `100ms` 节流，画布拖拽期间不重建 backing canvas。
- Rive 播放器动态拆包，本地图标替代 `@phosphor-icons/react`。入口 JS gzip 从约 `108.7 KB` 降到 `69.7 KB`；播放器在打开文件时再加载，gzip 约 `29.4 KB`。
- H5 构建链收敛为 Vite，锁文件包数从 `741` 降到 `232`；本轮 Vite 构建实测约 `0.25–1.04s`，生产和开发依赖审计均为 `0` 漏洞。
- Rive WASM 改为版本化地址 `rive-2.39.1.wasm`，构建自动生成 Brotli `573,290 B` 与 Gzip `743,520 B` 文件，Nginx 使用一年 immutable 缓存。
- 小程序上传源包从 `1,837,997 B` 降到 `1,631,271 B`（`1593.0 KB`）；排除重复原始样例、测试和历史构建，并设置 `1,700,000 B` 自动预算。
- 好友分享图从 `126,297 B` PNG 改为 `37,141 B` JPEG；手机详情和桌面分栏共用一份 WXML/WXSS 模板。
- 预览页改为组件后，所有 `SelectorQuery` 都固定 `query.in(this)`；组件 WXSS 只使用 `:host` 与类选择器，避免开发者工具拒绝标签或属性选择器。

### 复杂文件性能边界

- `.riv` 磁盘体积不等于运行复杂度；画板、嵌套实例、动画、状态机、矢量顶点、裁剪和持续 idle 才决定解析与逐帧成本。
- Animojis 测试文件为 `2.33 MiB`，但包含 `89` 个画板、`422` 条动画和 `86` 个状态机；默认 `3000 × 3000` 总览画板聚合整页表情，是当前真机性能样本。
- 首帧只解析并复用默认画板；其余画板由用户展开时分批读取，选中后才检查完整参数，避免首次进入同步创建大量运行时对象和标签。
- iOS 复杂无音频文件使用约 `24fps`、DPR 上限 `1.25`；暂停后停止持续绘制，交互、画布尺寸或参数变化时再按需重绘。
- 预览页提供性能、平衡、高清三档；普通 H5 默认高清（最高约 `60fps + DPR 2.0`），JOJO 托管版保持原有平衡档，微信小程序继续默认性能（约 `30fps + DPR 1.0`）并记住用户选择。复杂素材即使选择高清也保留自动安全上限。
- 微信未公开固定 CPU 或 iOS 内存配额，性能判断以目标真机分阶段计时、帧耗时和内存告警为准，不能用开发者工具流畅度代替。

Rive Web 运行时的通用音频链路通过兼容构造器桥接到 `wx.createWebAudioContext`。iOS Piano 使用专用资源加载器和 `BufferSource`，先显示首帧再按琴键优先顺序解码；单个解码超时会继续下一个，缺少琴键或解码失败时显式标记不可用，绝不回退到高负载混音。静音或离开预览会停止并释放音频；运行时只保留播放链路，不使用录音入口。

| `wx.shareFileMessage` | 发送原始 Rive 文件给好友 |
| `wx.saveFileToDisk` | 微信桌面端保存文件 |
| `wx.showShareMenu` | 分享小程序卡片与朋友圈入口 |
| `wx.setClipboardData` | 仅在用户点击复制图标后写入网页版预览地址 |
| `wx.createWebAudioContext` | 播放 Rive 文件内嵌音频，不采集声音 |
| `WXWebAssembly.instantiate` | 加载 Rive WASM 运行时 |

小程序不再包含 `web-view` 页面，也不会自动打开或强制跳转外部网站。网页版地址只作为与复杂 Rive 预览直接相关的辅助信息放在首页底部，原生预览、导入和文件管理仍可独立完成。

微信小程序不调用 `wx.getClipboardData`，也不读取剪贴板已有内容；仅在用户点击网址旁复制图标后调用一次 `wx.setClipboardData`。公众平台用途统一填写：“用于用户主动复制网页版预览地址，方便在浏览器中打开复杂 Rive 文件；仅向剪切板写入固定网址，不读取剪切板已有内容。”项目检查会阻止剪贴板读取、后台写入和其他复制用途。独立 H5 只在用户主动点击底部反馈入口时调用浏览器 `navigator.clipboard.writeText` 写入作者微信号。聊天文件导入只处理用户主动选中的 `.riv` 文件，文件在设备本地解析、预览和保存，不上传业务服务器。

当前按 `project.config.json` 忽略规则估算的小程序 Canvas 源包为 `1,666,466 B`，共 `66` 个文件，并由 `npm run check:package` 强制不超过 `1,700,000 B`。包内保留主版和兼容版两份 Rive Canvas WASM；H5、原始样例、测试、历史构建和依赖目录均已排除。

首页和预览页均声明 `onShareAppMessage`、`onShareTimeline`，并在页面显示时调用 `wx.showShareMenu`。好友卡使用 `share-friend.jpg`（500×400，约 37 KB）；朋友圈使用 `share-timeline.png`（272×272，约 14 KB）。若运行时返回 `showShareMenu:fail no permission`，应在公众平台检查账号权限，代码不能绕过平台拒绝。

本项目是微信原生小程序，不使用 Taro 的 `enableShareAppMessage` / `enableShareTimeline` 编译提示。微信原生页面与全局配置文档未列出这两个字段；本项目加入字段并重新编译实测后，分享菜单和 `no permission` 结果均无变化，因此不保留无效配置。

H5 同步小程序近期交互：首页主要点击入口使用中心放大回弹；托管根域名支持首页和详情页点击或拖入上传，首个 `.riv` 保存后立即从本机打开，预览与云端上传并行。公开中、最近查看和本机文件合并为一个按最近打开、评论或上传时间排序的列表，不再分“托管文件 / 最近文件”；但进入详情后，左侧列表切换文件只更新选中态，不再改变当前顺序。体积后依次用云勾、电脑、上云箭头或失败图标表达状态；云图标只展示状态，不再独立响应点击，首页与详情侧栏点击文件主区域的任意位置（包括云图标）都会选中并打开文件。上传中与失败仍在对应行内自动显示进度、错误和重试；文件菜单与重试保留独立操作。旧 `/rive-viewer/` 只保存到当前浏览器并隐藏公开链接入口。本地文件菜单保留“上传并生成链接 / 复制公开链接”和“发送文件”，不提供不可恢复移除。系统支持时“发送文件”调用 Web Share 文件面板，否则回退下载。画布手柄单击展开原位“完整 / 铺满”，按住或拖动时高亮并支持滑选；事件控制台位于参数区第一栏，公开评论紧跟其后，缩放方式位于最底部，背景色块为 `45×30px` 短胶囊。

H5 的“完整”模式会让预览画布按当前 Rive 画板宽高比居中收拢，在可用区域内保持比例，不再强制左右撑满；“铺满”仍使用整个可用画布。JOJO 托管版首次打开文件时默认使用“完整”，旧 `/rive-viewer/` 本地版仍默认“铺满”。详情参数区不再显示“文件操作”。托管文件详情在手机顶部栏与宽屏文件标题区都只保留下载和黄色“复制分享链接”；复制成功后按钮原位切换为普通深色样式、打钩图标与“已复制”，约 `2.2s` 后复位，不再打开详情分享弹层。旧本地入口仍只显示下载。文件列表的 Hover 背景由整行承接，连续覆盖到最右侧下拉箭头区域。

公开链接在新浏览器中会完整下载 `.riv` 后再解析。`getHostedFile` 使用 `ReadableStream` 按字节读取并展示真实百分比；20 秒未收到响应或 30 秒无新字节时进入可重试错误，不再无限停在“正在打开”。详情侧栏切换未缓存的云端文件时使用页面内路由，原详情结构保持可见，文件名读取后只在预览画布内显示下载和解析 Loading。下载完成后立即进入播放器，最近查看记录在后台保存，不再阻塞首帧。

当前生产主机、Node 与 Nginx 均未设置 GET 下载速度上限；服务器内部读取 `17,590,968 B` 的 `RFS` 约需 `0.03–0.10s`。2026-08-24 公网直连、代理与 SSH 实测长期吞吐约 `1–2 Mbps`，高度指向腾讯云公网带宽规格或云出口 QoS，代理只会额外造成波动。精确套餐值以腾讯云控制台为准；若长期托管 10–60 MB 文件，应提高公网带宽或把不可变 `.riv` 本体迁到腾讯云 COS/CDN。

H5 文件列表底部将“小程序”入口和纯文本“反馈意见：杨皓棱”并排展示；反馈文字不再是按钮，不提供复制行为。“小程序”使用 `WechatLogo`，悬停、键盘聚焦或触屏点击后，在入口上方展示“Rive 预览台”名称与本地小程序码。小程序码使用 `320×320` WebP，约 `32 KB`，不依赖外部图片服务。

### JOJO 横屏工作台

JOJO 托管版在浏览器宽度达到 `1194px`（iPad Pro 11 寸横屏）时使用可调双栏：左侧画布默认占满可用视窗高度并保持 Rive 文件原始宽高比，画布下方手柄继续支持手动调高；桌面优先把画面拉到约 `800px` 宽，再把剩余空间分给最小 `360px` 的右侧检查栏，中缝可用鼠标或键盘调整。左侧最近文件栏默认 `184px`，可在 `160–360px` 间拖动或键盘调整；文件名 Hover 或聚焦时在栏外浮层显示完整名称。低于该宽度保持上下布局。

## Rive 托管平台

正式入口为 <https://rive.mikeywa.site/>。用户在首页或详情页主动选择或拖入 `.riv` 后，文件先保存到当前浏览器并立即打开，再与预览并行顺序上传到云端；每个文件行显示真实百分比、失败重试或云端完成图标，三位短码与复制入口位于文件菜单。旧入口 <https://mikeywa.site/rive-viewer/> 保持纯本地预览版，避免旧 Origin 的 IndexedDB 文件丢失。

- 公开页为 `/<3 位短码>`；短码使用大小写敏感 Base62，`api` 为保留码，服务端生成时跳过并检查冲突。旧 `/s/<短码>` 使用 `308` 跳转到新地址。分享页复用 `WebRivePlayer`、`PlaybackTelemetry` 和完整 Rive WASM。
- 无用户系统，所有访问者权限相同。每个三位短码拥有独立评论区，切换文件时不复用上一文件的列表。评论仍只保留一个正文输入区；聚焦后在上方显示系统分配的萌萌森林头像和昵称。点击头像可选择本机图片，浏览器居中裁切并压缩为 `64×64 WebP`，只保留压缩结果；点击昵称可在本机修改，最多 `12` 个 Unicode 字符。发表时评论携带当前身份快照，其他人可见；本机设置不上传原始图片。无自定义时，浏览器随机访问标识继续稳定匹配 32 组默认身份；无法保存标识时才用 IP 与 User-Agent 的即时哈希兜底，不保存原始 IP。评论可归档和恢复，公开文件、本机文件与最近查看继续按短码去重合并，已归档文件通过首页“已归档”弹窗恢复。
- 文件只做“归档 / 恢复”，不提供永久删除。归档前二次确认；归档后原链接停止播放和新增评论，恢复后沿用原短码、评论和创建时间。
- 萌萌森林头像母版位于 `h5/assets/forest-avatars-master-4k.png`，尺寸为 `3840×1920`；母版是 `8×4` 方格，每格严格 `480×480px`。运行时使用 `h5/public/rive-viewer/avatars/` 下 32 张一一对应的不透明方形 WebP，单张严格为 `32×32px`；每张使用不同满版底色和大动物轮廓，由 `h5/scripts/build-forest-avatars.py` 按比例格线生成，避免透明边缘细缝和二次裁偏。
- 后端为 `server/` 下仅使用 Node 内置模块的单进程服务，监听 `127.0.0.1:8097`。文件保存在 `/var/lib/rive-host/files/`，状态以 `state.json` 原子更新，发布目录与数据目录分离。
- Rive 与 Lottie 单文件上限 `64 MiB`，PAG 单文件上限严格为 `10 MiB`；限制同时在浏览器与服务端执行。托管总量 `5 GiB`、最多 `10,000` 个分享；磁盘可用空间低于 `6 GiB` 时拒绝上传。单文件最多 `500` 条评论，全站最多 `5,000` 条评论。
- 每次上传都生成新的三位短码和独立评论区，即使文件字节完全相同也不复用旧短码；SHA-256 只用于完整性、ETag 和示例导入识别。Nginx 对上传和写操作按来源限速，归档与恢复要求 `X-Rive-Action` 确认头，页面和响应带 `noindex`。

### 托管 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/healthz` | 服务健康检查 |
| `GET / POST` | `/api/v1/shares` | 按状态与 `formats` 列出文件；上传 `.riv`、`.json` 或 `.pag` |
| `GET` | `/api/v1/shares/:code` | 获取分享元数据 |
| `GET / HEAD` | `/api/v1/shares/:code/file` | 下载文件，支持 Range 与 ETag |
| `GET / POST` | `/api/v1/shares/:code/comments` | 读取和提交纯文本评论 |
| `POST` | `/api/v1/shares/:code/comments/:commentId/archive` | 归档评论，要求确认头 |
| `POST` | `/api/v1/shares/:code/comments/:commentId/restore` | 恢复归档评论 |
| `POST` | `/api/v1/shares/:code/archive` | 二次确认后归档 |
| `POST` | `/api/v1/shares/:code/restore` | 恢复原分享链接 |

生产发布使用 `/opt/rive-host/releases/<时间戳>`、`/var/www/rive-host/releases/<时间戳>` 与原子 `current` 软链接；systemd 使用动态低权限用户，Nginx 只公开 HTTPS 和 `/api/` 代理。证书由 Certbot 自动续期，续签成功后会检查并重新加载 Nginx。

## 托管文件版本与多格式

正式入口 <https://rive.mikeywa.site/> 与 Beta 均可预览 `.riv`、自包含的 Lottie `.json` 与 `.pag`。详情页下载按钮左侧可“上传新版本”，新版本必须与原文件格式一致，沿用原三位短码并默认打开。文件名下拉可切换历史版本并显示上传日期。评论携带 `versionId`；只有两个及以上版本时才按“版本 N”分组，单版本沿用普通评论列表，不展示版本概念。

- `POST /api/v1/shares/:code/versions` 上传并设为当前版本；`GET /api/v1/shares/:code/file?versionId=<UUID>` 下载指定版本。
- Lottie 使用完整 Canvas 播放器并关闭渐进加载，只接受图片与字体已内嵌、没有外部资源 URL 的单个 JSON；PAG 使用 WebAssembly 播放器，超过 `10 MiB` 时直接拒绝，不进入上传队列。
- Lottie 与 PAG 使用可调高度的预览窗口，内部“完整”模式保持源文件比例并完整居中；PAG Canvas 强制跟随窗口内容区，禁止运行时写入的旧尺寸造成越界。
- 三种播放器均按格式动态加载。首屏不预加载 Rive WASM；完整 Lottie Canvas 运行时约 `69.1 KB gzip`，PAG WASM 为 `609.9 KB gzip`，后续由浏览器长期缓存。
- 分享元数据包含 `format`、`versions`、`currentVersionId` 和 `versionCount`；旧数据启动时自动识别为 Rive 并补为“版本 1”。正式版与 Beta 均显式请求三种格式；未传 `formats` 的旧客户端继续只收到 Rive，保持向后兼容。
- Beta 使用独立 IndexedDB `rive-viewer-h5-beta`，不会把最近记录写入正式页的 `rive-viewer-h5`。正式线上测试文件为 [Lottie `V1e`](https://rive.mikeywa.site/V1e) 与 [PAG `lOF`](https://rive.mikeywa.site/lOF)。
- 正式前端发布目录为 `/var/www/rive-host/releases/20260826-140429`；Beta 前端和兼容后端仍为 `20260826-132255`。

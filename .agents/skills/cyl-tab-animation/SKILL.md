> Since 2026-11-17 the component and its engine are their own pod, `CYLAnimatedItem` (`CYLAnimatedItem.podspec`: `Core`, `Engine`, one subspec per type; module `CYLAnimatedItem`), which depends on no other pod and must never depend on CYLTabBarController (only test code may; docs/Animated-Item.md, Structure); the subspec names below are kept and depend on it. Podfiles that take CYLTabBarController by path or commit also name `pod 'CYLAnimatedItem'`.
> The engine (animator protocols, registry, factory, players) is the `Engine` subspec of the separate pod `CYLAnimatedItem` (`CYLAnimatedItem.podspec`, module `CYLAnimatedItem`, which never depends on CYLTabBarController; Android: module `:cylanimateditem`, package `com.cyl.animateditem`). CYLTabBarController's Core depends on `CYLAnimatedItem/Core` (static images), never on an engine, and holds the tab buttons' side of the engine behind `CYL_ANIMATION_ENGINE_AVAILABLE`. Each type is a subspec `CYLAnimatedItem/<Type>` (`Engine` plus its library); the tab bar subspec `<Type>` (`LottieSwift`, `PAG`, `Rive`, `SVGA`, `GIF`…) is Core plus it, so tab bar Podfiles need one line (plus `pod 'CYLAnimatedItem'` by the same path or commit until it is on the trunk). The old names `CYLAnimationEngine` and `CYLAnimatedItem<Type>` are compatibility names. A new type: an animator in `CYLTabBarItemAnimation/<Type>/`, a `CYLAnimatedItem/<Type>` subspec, `CYL_<TYPE>_AVAILABLE` / `CYL_<TYPE>_REQUIRED` in `CYLAnimatedItemMacros.h`, its keys and a type-table row in `CYLAnimationKeys`, a tab bar subspec `<Type>`, and rows in the Android, HarmonyOS and mini program type tables. `CYLAnimatedItemView` shows static images unless the engine is in the build. A new animator registered there plays in tab buttons and in every `CYLAnimatedItemView` subclass of the other repositories. See [docs/Animated-Item.md](../../../docs/Animated-Item.md#enadding-an-animation-type).

# Animated tab icons

Steps for app developers: [Tab-Icon-Animation-Quick-Start](../../../docs/Tab-Icon-Animation-Quick-Start.md). **Tell the user to run the matching demo first** (`Example-PAG`, `Example-Rive`, `Example-Swift`) and tap a few tabs, so they see the effect before integrating. The tab selected at launch shows its last frame without playing (#389), so tell them to tap another tab. Design: [Tab-Bar-Item-Animation](../../../docs/Tab-Bar-Item-Animation.md). Source of truth: code, then `docs/`, then `README.md`. If they disagree, fix the wrong one first (usually `README.md`), then this skill.

- `pod 'CYLTabBarController'` alone has **no** animation code. Without a subspec the tabs show their images.
- **A GIF plays according to the key that gives it.** `CYLTabBarItemImage` or `CYLTabBarItemImageURL`: an image, it loops, no subspec. The GIF keys or generic animation keys: an animation, it plays once when selected. Tell the user which one they get.
- Every library works with Liquid Glass, FlatDesign and the classic tab bar. Check all three: `Example-GIF`, `Example-PAG` and `Example-Rive` switch from the navigation bar of the settings list, or with `-CYLDemoTabBarFlatDesign YES`. FlatDesign must be given as `styleType:` when the controller is created. On a simulator, check the classic tab bar on an iOS version before 26. PAG's OpenGL crashes the iOS 17.5 simulator on macOS 27 (`libCoreVMClient`): add `UIDesignRequiresCompatibility` to a copy of the built app's `Info.plist`, sign it again with `codesign -f -s - --deep`, and run it on iOS 26 instead.
- Android: `Example-Android/example-pag`, `example-gif` and `example-rive` are the twins of the iOS examples and read the same animation files ([Android-Examples](../../../docs/Android-Examples.md)); a GIF given as an image loops there too (`CYLGIFDrawable`).
- On the classic tab bar, a tab item's title change makes UIKit replace the tab's button. The library restores the animation on the new button (`-cyl_bindTabControlActions`). A page that sets `self.title` renames its tab: use `navigationItem.title` to keep the tab's title.
- Subspecs combine, and one tab bar can mix libraries and static tabs: [Per-Tab-Animation](../../../docs/Per-Tab-Animation.md).
- Demo files: name them by use (`tab_home.pag`). A tab shows the first frame until it is selected, so pick a small file whose first frame shows the icon; a full-screen poster or a file that starts empty looks like a blank or still tab. Check a new file's frames before using it.
- PAG and Rive files draw their own colors, and Liquid Glass ignores a background color in `standardAppearance`. White icons (the course's `icons.riv`) need a dark interface: the Rive demos set `overrideUserInterfaceStyle = .dark` on the tab bar controller.
- On a simulator several asynchronous `PAGView`s stall inside software OpenGL while holding their locks, which blocks the main thread: blank icons, no playback. The animator sets `-setSync:YES` on every target, so a simulator and a device run the same path. To debug playback, trace `-play` and `onAnimationUpdate:` rather than judging from screenshots.
- A configuration file (`-initWithConfiguration:`, [Configuration-File](../../../docs/Configuration-File.md)) takes the same keys as strings: the generic `CYLTabBarAnimation…` keys, PAG's, Rive's and GIF's keys (by name, whether or not the subspec is installed), `CYLTabBarAnimationOptions` (a dictionary written into the animation URL's fragment, e.g. `{"artboard": "HOME", "input": "active"}`), `CYLTabBarLottieLoopsWhenUnselected`, and the top-level `CYLTabBarControllerTabBarItemAnimationSpeed`.
- React Native and Flutter: the tab bar configuration takes the same keys; `CYLAnimationView` plays a file in a page through `CYLTabBarItemAnimationFactory` (options sorted into the URL fragment). Demos: `CrossPlatform/react-native-cyltabbar/example-pag` / `example-rive`, `CrossPlatform/flutter_cyltabbar/example_pag` / `example_rive`; see [Cross-Platform-Components](../../../docs/Cross-Platform-Components.md#enanimated-icon-demos). On Android the library calls `Rive.init` once (reflection) before the first Rive view; apps do not.
- WeChat Mini Program: the same keys through `cyl-tab-bar-item`, which picks `cyl-lottie`, `cyl-pag` (full libpag-miniprogram 4.5.85, WebAssembly + WebGL, vector PAG files; 4.4.76 fails in DevTools) or `cyl-rive` (`@rive-app/canvas-advanced` + WXWebAssembly) by file type. Package copies are `*.pag.bin` / `*.riv.bin`; the WebAssembly files are copied out of `miniprogram_npm` to `/cyl-rive-miniprogram/rive.wasm.br` and `/cyl-pag-miniprogram/libpag.wasm.br`. Each library is an optional package (`cyl-lottie-miniprogram`, `cyl-pag-miniprogram`, `cyl-rive-miniprogram`, `cyl-gif-miniprogram`); `cyl-tabbar-miniprogram` depends on none and takes their components through abstract nodes (`generic:cyl-lottie-view="cyl-lottie"`, `cyl-pag-view`, `cyl-rive-view`). Demo: `CrossPlatform/wechat-miniprogram-cyltabbar/example`, one package per setup (`npm run setup -- --animation=lottie|pag|rive|gif`); see [WeChat-Mini-Program](../../../docs/WeChat-Mini-Program.md).
- `tabBarItemAnimationSpeed` sets the speed. PAG files are downloaded by `scripts/fetch-animation-resources.py` at `pod install`, not kept in the repository.

## Rules for the library

- CYLTabBarController's Core and CYLUtils define no library switch. All switches are in the component's core, `CYLAnimatedItem/CYLAnimatedItemMacros.h`: `CYL_ANIMATION_ENGINE_AVAILABLE`, `CYL_LOTTIE_AVAILABLE` (library), `CYL_GIF_AVAILABLE`, `CYL_PAG_AVAILABLE`, `CYL_RIVE_AVAILABLE`, `CYL_SVGA_AVAILABLE` (the type's engine subspec plus its library), so every file can ask. Every type's keys always exist (declared in `CYLAnimationKeys.h`): without the engine they compile with a warning (`CYL_<TYPE>_REQUIRED`), debug builds log the pod to add (`CYLAnimationWarnMissingEngine()`; Android `CYLAnimationEngines`), and the tab shows its image or the placeholder. Only the animator sits inside its switch. The released Lottie keys stay defined and are marked `CYL_LOTTIE_REQUIRED`.
- A new library is one more folder, one more animator class and one more subspec, with no change anywhere else. The animator registers itself in `+load` with `CYLTabBarItemAnimatorRegistry`.
- Several engines in one app: never ask the app to register engines by hand. To confirm which are in, use `+[CYLTabBarItemAnimatorRegistry registrationReport]` (also logged once in DEBUG after launch), `+registeredIdentifiers`, `+isAnimatorRegisteredWithIdentifier:` and `+missingKnownIdentifiers` (Android: the same names on `CYLTabBarItemAnimatorRegistry`). A new animator picks a `priority` that no other animator claiming the same extension uses, or DEBUG logs a conflict. A new known type also goes into `CYLAnimationTypeTable()` (iOS) and `CYLAnimationEngines.types` (Android), so the report can name its subspec or dependency.
- Lottie is the fallback animator (`CYLTabBarItemAnimatorPriorityFallback`): it gets the files no other animator claims, but only takes a Lottie document (`CYLTabBarItemAnimationURLMayBeLottie()`: a JSON object with `layers`, or a `.lottie` archive with Lottie 4; a remote URL is judged once downloaded). A picture or a broken local file makes no animation view, so the static image or the placeholder stays. A new fallback animator must do the same: never make a view for a file it cannot play, or the static image is hidden.
- `CYLAnimatedItem.podspec` defines a module (`DEFINES_MODULE`), so `import CYLAnimatedItem` works in apps that build static libraries without `:modular_headers`.
- Rive's Metal shader warnings in the console (`program_source ... Compilation succeeded`) come from the `RiveRuntime` binary. They are harmless and cannot be fixed here.

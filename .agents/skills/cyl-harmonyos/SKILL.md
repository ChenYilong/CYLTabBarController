# HarmonyOS code

## The rule

All code of this project supports accessibility (screen readers, visual aids) and internationalization /
localization through localization files, including the HarmonyOS code. Where support is missing, add it first.
Automated UI tests use these features first to locate controls, to tap and to drive complex flows and consecutive
steps.

## Accessibility (ArkUI)

- Every control: `.accessibilityText(...)` with a localized text that includes its state (for a tab: title, "selected",
  badge such as "Messages, selected, 3 new"), `.accessibilityDescription(...)` when a hint helps, and a stable `.id(...)`
  for tests.
- A control made of several views (icon, title, badge): `.accessibilityGroup(true)` on the container so the screen
  reader reads it once.
- Decorations (glass lens, shadows, cover images): `.accessibilityLevel('no')`.
- Visual aids: sizes in `fp` for text so large-text settings apply; never carry meaning by color only; keep the
  contrast of titles and badges against the bar.

## Localization

- Texts come from string resources: `$r('app.string.<name>')` in ArkUI, `resources/base/element/string.json` (English,
  the fallback) and `resources/<language>[_<region>]/element/string.json` for each language.
- The strings are copied from CYLTabBarController's localization files
  (`CYLTabBarController/Resources/CYLTabBarController.bundle/<language>.lproj/CYLTabBarController.strings`), keeping only
  the keys the HarmonyOS code uses. Copy them with the script of the HarmonyOS module, not by hand, so all languages
  stay in sync.
- Never write a user-visible text in code.

## Score table

- `docs/HarmonyOS-API-Map.md` is generated by `scripts/harmonyos-api-map.py` from `scripts/harmonyos-api-map.json`.
- Each iOS symbol has a status: `done`, `partial` (with a note), `planned`, or `n/a`, shown as "TODO: N/A on HarmonyOS"
  with the reason (UIKit-only helpers, the Objective-C runtime, the iOS demo settings list...). `n/a` is left out of the
  score. Liquid Glass counts: the HarmonyOS tab bar implements it.
- When an API is implemented, write its HarmonyOS API and status into the JSON and regenerate the document.

## Building without an emulator

- Compile checks only: DevEco Studio's hvigor (`DEVECO_SDK_HOME=/Applications/DevEco-Studio.app/Contents/sdk`, the
  bundled node, `tools/hvigor/bin/hvigorw.js assembleHar --no-daemon`). Build in a copy outside the exFAT volume (`._*`
  files break hvigor).

## UI tests

- Locate controls with UiTest `ON.id('...')` first, then `ON.text('...')` with the localized text; tap, then check the
  selected state through the accessibility text. Coordinates are the last resort, and a control that cannot be found
  this way is a bug: add its id or accessibility text.

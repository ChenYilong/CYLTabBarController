### #569 — CYLBadge and CYLUtils extracted as independent libraries with a bottom-up dependency chain (GitHub)
decision · 2026-11-28 12:16 UTC
The Animated-Item-Badge design fixes the layering CYLUtils ← CYLBadge ← CYLAnimatedItem ← CYLTabBarController and the module name CYLUtilsKit.

The Animated-Item-Badge design settles on a bottom-up library layering so the badge can render on CYLAnimatedItem without a module cycle. Earlier the cycle CYLAnimatedItem→CYLBadge→CYLUtils→CYLAnimatedItem was found, and the owner resolved it by extracting CYLUtils as its own pod (D7). Lifecycle code is isolated behind CYLUtils (D8) so the lifecycle library stays generic.

- Decision D7: CYLUtils becomes an independent pod at the bottom, so the chain is CYLUtils ← CYLBadge ← CYLAnimatedItem ← CYLTabBarController.
- Decision D8: CYLUtils is the only direct dependency on the lifecycle library CYLDeallocBlockExecutor (~> 1.4), and the lifecycle library depends on nothing.
- Decision D1: the badge pod and module are named CYLBadge, with headers, class names, and sources unchanged.
- Decision D2 (amended in v3): the Liquid Glass rule moves to CYLUtils as isLiquidGlassActive() and liquidGlassActiveOverride, and CYLAnimatedItemView forwards to it.
- Decision D3: the unreleased cylBadgeSnapshotImage is removed, the demo uses badgeValue, and alignmentRectInsets alignment is kept.
- Decision D4: libraries that use only CYLAnimatedItem (CollectionViewClassifyMenu, CYLTableViewPlaceHolder) also pull in CYLBadge, CYLUtils, and CYLDeallocBlockExecutor; the owner accepted this.
- Decision Q7: the CYLUtils Swift module is named CYLUtilsKit (pod name CYLUtils), because a module and class with the same name break CYLUtils.Foo lookup and .swiftinterface generation.
- Five upward dependencies on CYLAnimatedItem inside CYLUtils must be cut: CYLUtilsMacros.h, CYLUtils.h, CYLSwiftInterface.h, the @_exported import in CYLUtils.swift, and the Liquid Glass rule.
- Podspecs are CYLUtils.podspec (module CYLUtilsKit, depends on CYLDeallocBlockExecutor), CYLBadge.podspec (depends on CYLUtils, frameworks UIKit and QuartzCore), and CYLAnimatedItem.podspec Core (depends on CYLBadge).

### #584 — CYLBadge extraction guide sets naming and lifecycle rules across all platforms (GitHub)
decision · 2026-11-28 12:16 UTC
The badge implementation guide defines naming, alignment, and CYLUtils gateway rules that every platform must follow.

The guide covers extracting a CYLBadge module and adding badge support to CYLAnimatedItemView across iOS, Android, HarmonyOS, WeChat Mini Program, React Native, and Flutter. Phase 1 extracts CYLBadge; phase 2 adds badgeValue, badgeAttributes, anchor, and reservesBadgeSpace. Naming follows a table where ObjC selector prefixes are mandatory only on types the project does not own, and project-owned members drop the prefix. Dependency lifecycle is centralized so only CYLUtils depends on the deallocation library and re-exports it, with greps as acceptance checks. The guide also lists common mistakes such as swapping "" and null meanings, composing icon and badge into one image, and committing with the animation switch on.

- The badge implementation guide (badge-cp.md) is bilingual, and the Animated-Item-Badge.md design doc is the source of truth; iOS wins on any conflict.
- Only iOS is released, so Android, HarmonyOS, WeChat Mini Program, React Native, and Flutter unreleased badge names are renamed directly with no aliases.
- Released iOS badge API is never changed; old import paths are re-exported after extraction.
- Naming rule: iOS ObjC category methods on types the project does not own keep the cyl_ selector prefix, while Swift uses cylFoo.
- Naming rule: project-owned type members (iOS, Android, HarmonyOS) have no prefix, and Android Kotlin extensions on platform types use cylFoo.
- Owner decisions N1 through N3: Android View.cyl_* becomes cylFoo directly; HarmonyOS CYLBadge.cyl_* becomes unprefixed directly; mini cyl_* methods become cylFoo directly.
- Value semantics on all platforms: nil/null/undefined means no badge, "" means dot, and any other value means text; the mini tab item's internal "" and "•" convention is a recorded platform difference.
- Lifecycle rule D8: CYLUtils is the only gateway to the cyldeallocblockexecutor library; CYLBadge, CYLAnimatedItem, and TabBar depend on it, not the library directly.
- Decision rule: read the existing badge implementation (step 0) before writing new code; path A aligns an existing CYLBadge, path B extracts scattered code as-is first and aligns after.
- Build-switch CYL_BADGE_ANIMATION_DISABLED moves to the cylbadge module build profile on HarmonyOS and is set on Android via -PcylBadgeAnimationDisabled.
